# KVFlow v0.1.0 — Initial Architecture and Simulation Prototype

## Overview

KVFlow is an exploratory simulator and systems architecture study for semantic
KV-cache orchestration in long-context LLM inference. It models how KV-cache
residency, movement, staging, and compression might be treated as first-class
runtime concerns as inference systems face growing pressure from long-context
decode, HBM capacity limits, and multi-tier memory placement.

This release establishes the first public prototype of the project and frames
KVFlow as a research-oriented inference-memory orchestration exploration, not
as production hardware or a benchmark-driven serving stack.

## Included in v0.1.0

- KV hierarchy simulator
- SRAM/HBM/CXL/DRAM tier modeling
- hot/warm/cold residency tracking
- simulated KV compression policies
- baseline vs KVFlow comparison mode
- exploratory metrics
- architecture documentation
- systems blog draft
- tests

## Current Limitations

- synchronous latency model in the initial exploratory results
- no realistic overlap yet in the original historical snapshot
- no real GPU kernel integration
- synthetic workloads
- exploratory metrics only

The current codebase has started to add overlap-aware pipeline accounting, but
the project should still be read as an approximate simulator rather than a
production runtime model.

## Why This Matters

Long-context inference increases persistent decode-time state, makes KV-cache
growth more expensive, and places more pressure on HBM capacity and bandwidth.
As multi-tenant serving becomes more common, movement and residency decisions
increasingly shape both performance behavior and serving cost. KVFlow exists to
study that transition in a controlled way.

## Related Industry Directions

- vLLM PagedAttention
- TensorRT-LLM KV cache reuse
- NVIDIA Dynamo routing
- CXL memory pooling

These directions suggest that the industry is already moving toward more
explicit KV management, even if the architectural endpoint is still emerging.
